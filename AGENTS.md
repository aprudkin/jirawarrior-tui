# jirawarrior-tui

Read-only обзор своих незавершённых задач Jira Server/Data Center для macOS.
Публичная команда — `jira-overview`, Python-пакет — `jira_overview`;
интеграции с Taskwarrior нет. Пользовательский контракт и рабочие сценарии —
в [README.md](README.md), зависимости и версии — в `pyproject.toml` и `uv.lock`.

## Границы изменений

- `src/jira_overview/core.py`: GET-only Jira API, полная пагинация, снимки,
  изоляция и атомарная запись локальных меток просмотра.
- `src/jira_overview/app.py`: Textual UI, асинхронное обновление и передача
  ссылки браузеру; подтверждается показанный снимок, а не более свежие данные.
- `src/jira_overview/__main__.py`: TOML, токен из окружения, CLI и `--check`.
- `tests/`: синтетические HTTP/Textual, установленная команда и Go Task.
  При изменении поведения добавляй регрессионную проверку на этой границе.

Сохраняй GET-only контракт, проверку TLS, отказ от редиректов и последний
успешный снимок при ошибке. Локальные метки — не серверный статус прочтения.
Команду, XDG-пути и формат состояния меняй только в рамках явно порученной
совместимости/миграции. `Taskfile.yml` — необязательные обёртки установленного CLI,
не требование для запуска приложения.

## Разработка и проверки

Команды выполняются из корня проекта. Подготовка окружения:

```sh
uv sync --frozen --python 3.12
```

Полный набор (unittest, не pytest):

```sh
PYTHONDONTWRITEBYTECODE=1 uv run --frozen python -m unittest discover -s tests -v
```

Go Task нужен только трём тестам обёрток; без него они пропускаются.
Учитывай пропуски отдельно от успешных проверок. Статический typechecker и CI
пока не настроены; наличие глобального языкового сервера не заменяет проверку.

## Завершение и доставка

По умолчанию завершённые изменения этого проекта доставляй до используемой
команды: **проверки → main → push → обновление установленного jira-overview**.
Это постоянное разрешение владельца: отдельного поручения на merge или
обновление существующей uv tool-установки не требуется. Публикация только
рабочей ветки — промежуточный результат, не завершение поручения.

Сохраняй применимые Git-проверки, историю и чужие изменения. Проверяй
объединённый результат до продвижения main; обычным push публикуй только
проверенные коммиты и подтверждай remote SHA. Существующую установку
обновляй из этого точного опубликованного SHA, а не из плавающего ref.
Подтверждай происхождение установленного пакета, запуск `jira-overview --help`
вне checkout и синтетические регрессии на установленном пакете. Установка
не должна менять приватные TOML, PAT, XDG-пути и локальную историю меток.

Явные ограничения пользователя («только обсудить», «только issue»,
«не сливать», «не обновлять» и другие) имеют приоритет; это правило не
запускает непорученную реализацию. При реальном блокере сохрани достигнутое
состояние и назови недоставленный остаток. В итоговом статусе различай
опубликованный main, установленный commit и проведённые проверки.
Новый тег/release и живая Jira автоматически в доставку не входят.

## Приватность и живая приёмка

Обычная регрессия использует синтетические данные, loopback-сервер и временное
состояние; браузер перехвачен. Живая приёмка с Jira — отдельный сценарий README:
`--check` делает сетевые GET, TUI пишет локальные метки, открытие меняет их.
Запускай его только в рамках поручения, требующего живой проверки.

PAT, приватный TOML, файлы состояния (включая ID задач), сырые ответы Jira и
терминальные логи оставляй вне Git и публичных issues. Ошибки должны оставаться
без URL, токена и тела ответа. Для примеров используй синтетические адреса
и данные. Глобальные Taskfile, shell-конфигурация и Pi-настройки не являются
частью этого репозитория.
