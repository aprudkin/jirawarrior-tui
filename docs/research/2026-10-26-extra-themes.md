# Дополнительные темы для jirawarrior

Исследование для [#31](https://github.com/aprudkin/jirawarrior-tui/issues/31),
2026-10-26. Поручен поиск вариантов, не добавление тем или обновление установки.
База исследования: `faffd801dad36e8e221fb5fab8997839804a34e0`, Textual 6.6.0,
Python >=3.11 (рекомендуемое окружение проекта — Python 3.12).

## Вывод

Дополнительные палитры можно встроить в существующую панель «Темы» без обновления
Textual и без новой обязательной зависимости. Для этого нужны локальные определения
`Theme`, зарегистрированные до построения панели и загрузки сохранённого имени.
Ниже перечислены кандидаты для адаптации, а не уже добавленные или визуально
проверенные в jirawarrior темы. Конфиг редактора/терминала сам по себе не является
плагином Textual.

Для первого небольшого набора рекомендованы **6 палитр**: Rosé Pine, Rosé Pine Dawn,
Everforest Dark, Everforest Light, Kanagawa Wave и Gruvbox Light. Это рекомендация
по разнообразию: три тёмных и три светлых, без заполнения списка близкими вариациями.
Можно ничего не добавлять: существующие 11 тем уже покрывают основные режимы;
новые нужны для других оттенков, а не для исправления функционального недостатка.

## Готовые наборы и совместимость

- [`textual-everforest` 0.1.0](https://pypi.org/project/textual-everforest/0.1.0/)
  предоставляет register-ready dark/light hard/medium/soft. Проверенные
  [метаданные PyPI](https://pypi.org/pypi/textual-everforest/0.1.0/json):
  `requires_python = ">=3.13"`, `requires_dist = ["textual>=0.61"]`.
  Ограничение Textual допускает 6.6.0, но это не runtime-проверка совместимости.
  Минимум Python исключает поддерживаемые проектом 3.11/3.12, поэтому добавлять
  пакет как обязательную зависимость не рекомендуется. Сами палитры можно
  адаптировать без него и без смены Python.
- [`textual-nvim-themes`](https://github.com/Fosox/textual-nvim-themes) — сторонний
  адаптер с собственным API `ThemedApp`. Совместимость именно с Textual 6.6.0
  не подтверждена; включать такой слой ради нескольких статических палитр незачем.
- Специализированные готовые пакеты для остальных кандидатов в выполненном поиске
  не подтверждены. Это не доказательство их абсолютного отсутствия.
- Перед копированием конкретных цветов/кода следует проверить применимую лицензию
  выбранного upstream и сохранить требуемую атрибуцию. Здесь сторонние палитры
  в код проекта не скопированы.

## Локальная проверка механизма

В установленной в `.venv` Textual **6.6.0** проверены определения `Theme`,
`App.register_theme` и `App.available_themes`; панель приложения использует
последнее свойство. Источники:
[`themes.py`](../../src/jira_overview/themes.py),
[`app.py`](../../src/jira_overview/app.py),
[исходник Textual 6.6.0](https://github.com/Textualize/textual/blob/v6.6.0/src/textual/theme.py).

Синтетический headless-запуск Textual проверил две временные темы (тёмную/светлую):
регистрация → наличие в существующем `ThemePanel` → активация → генерация
CSS-переменных → запись и чтение имени через существующие `write_theme/read_theme`
во временном каталоге. Результат: **PASS**.

Фактические 11 цветовых тем этой версии: `textual-dark`, `textual-light`, `nord`,
`gruvbox`, `catppuccin-mocha`, `catppuccin-latte`, `dracula`, `tokyo-night`,
`monokai`, `flexoki`, `solarized-light`. `textual-ansi` исключён по контракту.
В частности, Solarized Dark и One Dark/Light здесь **не встроены**; сведения
документации других версий не заменяют эту локальную сверку.

Проверка подтверждает механизм расширения, но не готовность конкретных новых
палитр: при реализации останется проверить читаемость курсора, NEW/Comment,
таблиц, ошибок и обеих панелей, предпросмотр/отмену/сохранение/перезапуск.
Полный unittest-набор в рамках документального исследования не запускался.
Код, зависимости и установленная команда не изменены; живая Jira, браузер,
приватная конфигурация и пользовательское состояние не использовались.
