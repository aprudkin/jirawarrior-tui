# Domain docs

Проект использует **single-context**: один словарь
[GLOSSARY.md](../../GLOSSARY.md) и, по мере появления реальных решений, `docs/adr/`.
Каталог ADR пока не создан; пустые документы для наличия структуры не нужны.

Перед исследованием читай словарь и относящиеся к области ADR, если они есть.
Пользовательские сценарии и контракты сверяй с [README.md](../../README.md),
реализацию — с кодом и тестами. Различай GitHub issue разработки и задачу Jira,
которую показывает приложение.

Сохраняй определения «jirawarrior-tui» и «Локальные метки просмотра»:
read-only не означает редактор Jira, а NEW/непросмотренные комментарии —
не доказательство чтения человеком и не синхронизируемое состояние Jira.

При появлении нового предметного термина или значимого архитектурного решения
используй skill `domain-modeling`: дополни существующий словарь либо запиши
непустой ADR в `docs/adr/`, сохраняя язык документации. Сначала сообщи
о противоречиях словаря, README и кода; не исправляй их молчаливым переименованием.
