## 0.2.0

Обновление с **0.1.0**: команда `jira-overview` заменена на **`jirawarrior`**
и **`jw`**; обновите вызывающие её скрипты и ранее скопированные Taskfile.
TOML, XDG-пути и формат локальной истории совместимы, сброс данных не нужен.
В отличие от read-only выпуска 0.1.0, теперь есть одно явное действие записи
в Jira — **A → Спринт**. Обычный обзор и `--check` по-прежнему GET-only.

- Подзадачи показаны непосредственно под родителями непрерывными семейными
  блоками: в обеих обычных областях отступ два пробела, в режиме эпиков —
  «эпик → задача → подзадачи» с отступами два/четыре. Положение семьи определяет
  только родитель; дети сохраняют собственные статусы, даты и метки.
  Чужие/закрытые/исключённые родители и копии родителя в другой области —
  контекст без локальных меток, увеличения счётчиков и подтверждения истории.
- `a — Спринт` добавляет одну выбранную обычную задачу в активный спринт:
  один — сразу, несколько — явный выбор с отменой. Эпики, подзадачи и перенос
  из другого active/future спринта исключены. Результат сверяется чтением Jira,
  обзор обновляется с сохранением выбора и локальных меток. Это единственная
  запись в Jira; обычный обзор и `--check` остаются GET-only.

- `/` включает мгновенный локальный фильтр названий без учёта регистра,
  включая кириллицу. Enter возвращает навигацию с сохранённым запросом,
  Esc очищает его. В режиме эпиков совпавшие дети сохраняют родительский
  контекст. Обновление сохраняет запрос; ввод не делает HTTP и не меняет метки.
- Внутри каждого статуса и блока `NEW` → `Comment` → обычные задачи и семейные
  блоки по родителю идут по последнему изменению Jira (`updated`), свежие сверху;
  при равном времени — по ключу, неизвестные даты — в конце группы.
  Дети внутри семьи сортируются по тем же правилам по собственным полям. Правило действует в обеих областях
  и внутри эпиков, сохраняя порядок статусов, самих эпиков и выбранную задачу.
  Новая колонка «Обновлено» показывает только дату в локальном часовом поясе,
  `ДД.ММ.ГГГГ` или `—`; сортировка учитывает полное время с долями секунды.
- Представление обзора, режим эпиков, размеры таблиц и сохранение выбора
  сосредоточены в `OverviewPresentation`. Пользовательское управление и форматы
  хранения не изменены; добавлены прямые проверки представления без сети.
- В панель «Темы» добавлены Rosé Pine, Rosé Pine Dawn, Everforest Dark/Light
  (medium), Kanagawa Wave и Gruvbox Light: всего 17 тем, 11 тёмных и 6 светлых.
  Без новых зависимостей, смены стандартной темы или формата сохранённого выбора.
  Источники палитр и MIT-уведомления включены в поставку пакета.
- Открытие задачи мышью — по Ctrl+щелчку левой кнопкой, в том числе в режиме
  эпиков. Обычный и двойной щелчок только выбирают строку, не снимая метки;
  Enter и подтверждение показанного снимка после принятия ссылки сохранены.
- При занятом профиле `p` ищет другой экземпляр и показывает PID в отдельном
  подтверждении с отменой по умолчанию. После повторной проверки владельца
  «Завершить» отправляет один SIGINT, а освобождение lock запускает обновление.
  Неизвестный/сменившийся владелец не завершается, эскалации и удаления файлов нет.
- Задачи со статусом `Verifying` (без учёта регистра) исключены из основной
  выборки без удаления локальной истории; контекстные родители остаются видимыми.
  Только среди остальных задач статус `Open` имеет приоритет перед `In Progress`
  внутри каждого блока меток. Отдельная колонка «Спринт» удалена, сведения об
  активных спринтах остаются в заголовке области.
- Интервал автообновления по умолчанию увеличен с 60 секунд до 60 минут
  (`refresh_seconds = 3600`). Явное значение в существующем TOML сохраняет
  приоритет, если интервал ещё не сохранён через меню; начальная загрузка
  и ручное обновление по R работают как прежде.
- `s` открывает правую панель «Настройки» с пунктом «Интервал обновления».
  Enter/щелчок открывают ввод **минут** (включая дробные), Enter сохраняет и сразу меняет расписание,
  Esc/повторное `s`/× отменяют ввод. Отдельный атомарный `settings.json` хранит
  предпочтение между запусками с приоритетом над TOML, не меняя историю Jira.
  Панели настроек и тем взаимоисключающие; цвет индикатора не изменён.
  В TOML и `settings.json` интервал по-прежнему в секундах, прежние значения
  сохраняют длительность и не требуют миграции.
- Верхняя строка показывает время следующего автообновления с учётом расписания
  и `Retry-After`. Во время загрузки вместо него — анимированный точечный
  индикатор и `Updating`; время последней успешной загрузки сохраняется.
- Палитра команд полностью отключена. `t` открывает правую панель «Темы»:
  тёмные, затем светлые; перемещение и щелчок сразу показывают цвета.
  Enter атомарно сохраняет тему между запусками, Esc/повторное `t`/× отменяют
  предпросмотр. Настройка хранится отдельно от истории Jira в `theme.json`.
- Верхняя строка показывает `Jira Warrior: <имя>` без технического идентификатора
  пользователя; время обновления и индикация устаревшего снимка сохранены.
- Подпись переключателя `e` сокращена до «Эпики». Спринты с именем вида
  `DEMO-2026-W43` отображаются в заголовке как «43-я неделя»; остальные имена
  сохраняются вместе с ID.
- Обычные области используют общую ширину колонок: статусы выровнены независимо
  от длины ключей, меток и названий. Ширины пересчитываются после обновлений,
  включая уменьшение после исчезновения длинных строк.
- Эпики скрыты из обычных областей. `e` (также кириллическая `е`) переключает
  единый список эпиков с собственными открытыми тикетами и возвращает обычный вид.
  Поддержаны пустые свои, чужие/закрытые родительские эпики и подзадачи через
  родителя; контекстные эпики открываются без создания локальных меток.
- Основная команда переименована в `jirawarrior`, добавлен короткий алиас `jw`.
  Команда `jira-overview` больше не устанавливается; вызывающие её скрипты
  и ранее скопированные Taskfile нужно обновить.
- Репозиторные Go Task-обёртки запускают `jirawarrior`; их имена сохранены.
- Python-модуль `jira_overview`, пути TOML/состояния `jira-overview`, переменные
  окружения и формат локальных меток сохранены, миграция данных не нужна.

## 0.1.0

Первый самостоятельный публичный выпуск **jirawarrior-tui**.

- Read-only обзор собственных незавершённых задач Jira Server/Data Center:
  текущий спринт и остальные задачи, обновление, открытие в браузере.
- Локальные `NEW`/непросмотренные комментарии с сохранением между запусками.
- Сохранены `jira-overview`, пути конфигурации/состояния и формат профиля v1.
- Установка через uv из Git-тега `v0.1.0`, без checkout ossetup.
- Необязательные `t jira` / `t jira:check` вызывают установленную команду.
- Поддерживается только macOS; Jira Cloud, запись в Jira, PyPI/Homebrew,
  фоновые службы и интеграция с Taskwarrior в выпуск не входят.
- MIT для собственного кода, сохранённая атрибуция и перечень лицензий зависимостей.

Проверки каждого выпуска фиксируются в его GitHub Release.
Для **0.1.0** они также сохранены в итоговом комментарии `aprudkin/ossetup#14`. Синтетические тесты не заменяют
живую read-only приёмку и не доказывают чтение страницы человеком.
