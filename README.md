# jirawarrior-tui

Read-only TUI для своих незавершённых задач в **Jira Server/Data Center**:
две области **«Текущий спринт»** и **«Остальные мои задачи»** без эпиков,
переключаемый режим **«Эпики»**, локальные метки `NEW` и `Comment +N`, обновление и открытие задачи в браузере.
Основная команда — **`jirawarrior`**, короткий алиас — **`jw`**.
Команда `jira-overview` удалена. Интеграции с Taskwarrior нет.

Первый выпуск поддерживает **только macOS**, Python **3.11+**,
[uv](https://docs.astral.sh/uv/) и Git для установки из репозитория.
Linux, Windows, Jira Cloud, Basic auth, cookies, запись в Jira и командные
дашборды не поддерживаются. Нужен Jira Software с доступным Agile API и Bearer PAT;
наличие PAT в Server/DC само по себе не гарантирует совместимость всех API.
Приложение не устанавливает фоновые службы и не меняет настройки системы.

## Установка

Команды `jirawarrior` и `jw` доступны в текущей **main**, пока без нового
тега/release. Опубликованный тег **v0.1.0** содержит только прежнюю команду
`jira-overview`. Установите текущую main в отдельное uv tool-окружение
(если приложение уже установлено, эта команда обновит его):

```sh
uv tool install --force --refresh-package jirawarrior-tui --python 3.12 'git+https://github.com/aprudkin/jirawarrior-tui.git@main'
```

Python 3.12 выбран для воспроизводимого сценария первого выпуска; uv при
необходимости загрузит интерпретатор. Клон `ossetup` или этого проекта для
запуска не нужен. Если каталог uv tools ещё не в PATH, выполните `uv tool update-shell`
и откройте новый терминал. После установки из любого каталога:

```sh
jirawarrior --help
```

Для короткого запуска используйте `jw`: это тот же CLI с теми же аргументами.

Textual **6.6.0** и HTTPX **0.28.1** закреплены в метаданных пакета.
`uv.lock` закрепляет транзитивные зависимости **для разработки через `uv sync --frozen`**;
`uv tool install` из Git использует метаданные пакета, а не этот lockfile.
PyPI/Homebrew-публикации нет. См. [описание выпуска](CHANGELOG.md).

## Конфигурация и PAT

Создайте приватный `~/.config/jira-overview/config.toml` либо
`$XDG_CONFIG_HOME/jira-overview/config.toml` по [синтетическому примеру](config.example.toml):

```toml
url = "https://jira.example.org/jira"
token_env = "MY_JIRA_TOKEN"
refresh_seconds = 3600
# state_dir = "~/.local/state/jira-overview"
```

Замените только адрес и, при необходимости, имя переменной. `url` — HTTPS-адрес
instance с возможным context path, без `/rest/...`, query и fragment.
TOML храните вне Git с доступом только владельцу. Пример не содержит реальных
адресов, токена или ID и не является рабочей корпоративной конфигурацией.

По [инструкции Atlassian](https://confluence.atlassian.com/enterprise/using-personal-access-tokens-1026032365.html)
PAT создаётся в Jira через **аватар → Profile → Personal access tokens → Create token**.
Задайте имя и срок действия, скопируйте токен в защищённое хранилище: повторно
показать его нельзя. Если раздел недоступен, обратитесь к администратору;
приложение не обходит политику instance. PAT наследует права пользователя и
**не становится read-only** от использования этим клиентом: GET-only — контракт
приложения, а не ограничение возможностей украденного PAT. Используйте минимально
необходимые права и отзовите скомпрометированный токен в том же разделе Jira.

`token_env` — **имя** экспортированной переменной окружения, не сам токен.
Приложение не читает shell-файлы и не загружает `.env`. Предпочтителен уже
настроенный менеджер секретов. Для разовой сессии **zsh** можно ввести PAT скрыто,
без помещения значения в команду или shell history:

```zsh
read -rs 'MY_JIRA_TOKEN?Bearer PAT: ' && export MY_JIRA_TOKEN
```

Не записывайте PAT в TOML, аргументы команд, Git, скриншоты или отчёты.
Переменную наследуют дочерние процессы терминала. После работы удалите её
из текущей сессии командой `unset MY_JIRA_TOKEN`.

Проверка соединения, включая все страницы комментариев, **без UI и записи состояния**:

```sh
jirawarrior --check
```

Она печатает только итог и количества: без URL, имени пользователя, ключей
задач, комментариев или токена. Для другого TOML есть `--config`.
Открыть TUI:

```sh
jirawarrior
```

## Необязательные `t jira` / `t jira:check`

Go Task не нужен для прямого запуска. Если он уже установлен, сохраните
[Taskfile.yml](Taskfile.yml) из текущей main вне репозитория:

```sh
curl -fL --create-dirs --output "$HOME/.config/jira-overview/Taskfile.yml" https://raw.githubusercontent.com/aprudkin/jirawarrior-tui/main/Taskfile.yml
```

Добавьте или замените **только** запись `jira` в существующем `includes`
глобального Taskfile, не заменяя другие задачи и не создавая второй `includes`:

```yaml
includes:
  jira:
    taskfile: ~/.config/jira-overview/Taskfile.yml
    optional: true
    flatten: true
```

Обёртки вызывают установленный `jirawarrior` / `jirawarrior --check`,
наследуют окружение, сохраняют TTY и не зависят от checkout или `uv run`.
Канонические имена — `open:jira` / `check:jira`, алиасы — `jira` / `jira:check`.
Для zsh короткий глобальный вызов с сохранением кода ошибки задаётся так:

```zsh
alias t='noglob command task --global --exit-code'
```

После этого доступны `t jira` и `t jira:check` из любого каталога.
Без алиаса используйте `task --global --exit-code jira` или
`task --global --exit-code jira:check`. `--exit-code` сохраняет точный код
дочерней команды. Отсутствующий optional include не мешает остальным задачам.

## Переход с ossetup

В текущей main запуск переименован: вместо `jira-overview` используйте
`jirawarrior` или `jw`. Старый исполняемый файл больше не устанавливается;
обновите вызывающие его скрипты и ранее скопированный Taskfile по инструкции выше.
Python-модуль `jira_overview`, TOML, XDG-переменные и каталог состояния
`jira-overview` сохранены. При переносе из ossetup имя дистрибутива изменилось:
`ossetup-jira-overview` → `jirawarrior-tui`. **Не удаляйте состояние ради переноса**:
baseline, `NEW` и непросмотренные комментарии не требуют миграции или сброса.
Завершите старый экземпляр перед запуском нового — профиль защищён lock.

Если использовался старый Go Task include `~/dev/ossetup/jira-tui/Taskfile.yml`,
замените только его путь по инструкции выше после установки нового пакета.
Не запускайте две копии одновременно. Единственный поддерживаемый исходник —
этот репозиторий; история `ossetup` не импортирована, атрибуция сохранена
в [NOTICE.md](NOTICE.md).

## Управление

| Действие | Клавиша / жест |
| --- | --- |
| Выбор строки | ↑ / ↓; Ctrl+Home / Ctrl+End; PageUp / PageDown; обычный щелчок |
| Переключение области | Tab / Shift+Tab |
| Открытие задачи | Enter или Ctrl+щелчок левой кнопкой по строке |
| Ручное обновление | R |
| Режим эпиков / обычный список | E (также кириллическая `е`) |
| Правая панель «Темы» | T или щелчок по «Темы» в нижней строке |
| Правая панель «Настройки» | S или щелчок по «Настройки» в нижней строке |
| Найти занявший профиль экземпляр | P — только при ошибке занятого профиля |
| Выход | Q или Ctrl+C |

Обычный щелчок (включая двойной) только выбирает задачу, не открывает браузер
и не снимает `NEW`/`Comment`. Для открытия мышью удерживайте **Control (⌃)**,
не Command (⌘) и не Option (⌥): Cmd не передаётся протоколом мыши Textual.
Ctrl+щелчок, как и Enter, подтверждает только показанный снимок после принятия
ссылки браузером. Это правило действует и для эпиков.

### Темы

`t` открывает справа панель **«Темы»**, сужая обзор без затемнения. При открытии
выделена текущая тема. В списке сначала **«Тёмные»**, затем **«Светлые»**,
внутри групп — по алфавиту. Доступны **17 цветовых тем: 11 тёмных и 6 светлых** —
11 встроенных тем Textual 6.6.0 и 6 дополнительных палитр:

- **Тёмные:** `rose-pine`, `everforest-dark`, `kanagawa-wave`.
- **Светлые:** `rose-pine-dawn`, `everforest-light`, `gruvbox-light`.

Everforest использует вариант medium. Новые палитры включены в приложение,
не требуют дополнительных пакетов, Neovim или смены Python. Прежние темы и
сохранённый выбор совместимы; стандартная тема не меняется. Источники и лицензии —
в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
ANSI-режим, использующий палитру терминала, в этот список не входит.
Палитра команд полностью отключена: **Ctrl+P больше ничего не открывает**.

- **↑/↓, PageUp/PageDown, Home/End или щелчок** сразу показывают цвета выбранной
  темы во всём приложении. Щелчок — только предпросмотр, не сохранение.
- **Enter** сохраняет тему между запусками и закрывает панель.
- **Esc, повторное `t` или ×** отменяют предпросмотр и возвращают прежнюю тему.
- При закрытии восстанавливаются область и выбранная задача, в том числе после
  обновления. Пока панель открыта, Enter и щелчки по таблицам не открывают Jira,
  режим эпиков не переключается; ручное и автоматическое обновление продолжаются.
- **Q / Ctrl+C** выходят без сохранения неподтверждённого предпросмотра.

Подтверждённая тема записывается атомарно в отдельный `theme.json` в используемом
каталоге состояния: `state_dir` из TOML либо `$XDG_STATE_HOME/jira-overview`
(по умолчанию `~/.local/state/jira-overview`). Настройка общая для профилей в этом
каталоге; файл содержит только версию и имя темы, без сведений Jira. Приватный
TOML и история локальных меток не переписываются. При ошибке сохранения панель
остаётся открытой, прежняя настройка сохраняется; можно повторить Enter или
отменить выбор. Повреждённая или недоступная сохранённая тема не мешает обзору:
показываются стандартная тема и предупреждение.

Загрузка пользовательских файлов и редактор тем не поддерживаются.
Другие палитры можно включить отдельным изменением приложения.

### Настройки

`s` открывает справа панель **«Настройки»** в том же стиле, что «Темы»,
без затемнения обзора. Пока доступен один пункт — **«Интервал обновления»**
с текущим значением в минутах.

- **Enter или щелчок по пункту** открывает поле ввода с выбранным текущим значением.
  Введите интервал в **минутах** и нажмите **Enter** для сохранения.
  По умолчанию — **60 минут**. Допускаются дробные минуты через точку, например
  `1.5` — полторы минуты. Диапазон — от **1/12 до 1440 минут**;
  нижнюю границу можно ввести как `0.08333333333333333`.
- Успешное сохранение закрывает панель и сразу меняет расписание:
  следующий автоматический цикл — через новый интервал от момента изменения.
  Уже идущая загрузка не прерывается, ограничение `Retry-After` сохраняется.
- **Esc, повторное `s` или ×** закрывают панель без сохранения ввода.
  Неверное значение или ошибка записи оставляют панель открытой и не меняют
  действующий интервал; сообщение не содержит приватных путей или данных Jira.
- Панели «Темы» и «Настройки» не открываются одновременно. Переход по `t`/`s`
  отменяет неподтверждённый выбор в предыдущей панели. После закрытия возвращаются
  фокус и выбранная задача. Пока панель открыта, задачи не открываются в браузере
  и режим эпиков не переключается; ручное **R** и автоматическое обновление работают.
  **Q / Ctrl+C** выходят без сохранения незавершённого ввода.

Интервал сохраняется атомарно в отдельном **`settings.json`** в том же каталоге
состояния, что `theme.json`. Файл содержит только версию и `refresh_seconds`,
без сведений Jira. В меню используются минуты, а в TOML и `settings.json` —
по-прежнему секунды: прежние настройки совместимы без миграции.
Сохранённое через меню значение **имеет приоритет над TOML**
при последующих запусках TUI и общее для профилей в этом каталоге состояния.
Если файл отсутствует, используется `refresh_seconds` из TOML либо 3600 секунд;
если повреждён или недоступен — то же значение и безопасное предупреждение.
Приватный TOML и история локальных меток при работе меню не переписываются.

### Области обзора

Высота «Текущего спринта» подстраивается под список: после таблицы (включая
горизонтальную полосу прокрутки, если она нужна) остаётся ровно **одна пустая
строка**, затем начинается «Остальные мои задачи». При обновлении и изменении
размера окна начало нижней области пересчитывается. Длинный спринт ограничен
по высоте, чтобы обе области оставались видимыми и прокручивались независимо.
Горизонтальная прокрутка — стрелки влево/вправо и Home/End; ключ и метки находятся
в первом столбце. Рекомендуемый
минимум терминала — 45×16. В обеих таблицах четыре столбца: «Тикет», «Название»,
«Статус» и «Обновлено»; отдельного столбца «Спринт» нет. Ширины колонок общие для обеих
областей и определяются по их содержимому вместе с заголовками и метками:
«Статус» начинается на одной горизонтальной позиции при одинаковой прокрутке.
После обновления ширины пересчитываются, в том числе уменьшаются после удаления
длинных строк или снятия меток. Широкие и комбинируемые символы учитываются
в терминальных ячейках; длинный текст остаётся доступен горизонтальной прокруткой.
Активные спринты показаны в заголовке верхней области: имена вида
`DEMO-2026-W43` отображаются как «43-я неделя», без префикса, года и ID.
Для имён другого формата сохраняются имя и ID. Задача остаётся одной строкой
даже при нескольких активных спринтах. Верхняя строка содержит `Jira Warrior: <имя>`
без технического идентификатора пользователя, время последней успешной загрузки
и `Следующее обновление HH:MM:SS TZ` в локальном часовом поясе. Во время начальной,
ручной или автоматической загрузки вместо следующего времени показываются
анимированный точечный индикатор и `Updating`; время последнего успеха остаётся.
Jira-текст выводится без Rich-разметки и управляющих символов.

В обычном режиме эпики скрыты в обеих областях; остальные задачи, включая
задачи без эпика, остаются на своих местах. В каждой области сначала идут задачи с `NEW` (в том числе с обеими метками),
затем только с `Comment`, затем обычные. Этот порядок важнее статуса Jira;
задача остаётся в своей области и показывается один раз. Это порядок строк,
не закрепление на экране при прокрутке. Дополнительных заголовков меток нет.

Внутри каждого из трёх блоков задачи сгруппированы по точному названию статуса:
одинаковые названия объединяются, в том числе между проектами; разные названия
остаются отдельными группами. Непустые группы всегда раскрыты, без названий
и счётчиков групп. В обеих областях строки задач идут подряд, без пустых строк перед первой
группой и между группами. Статус по-прежнему виден в столбце «Статус».
Порядок приоритетов (названия сравниваются
без учёта регистра только для определения приоритета): **In Progress / В работе**,
**To Do / К выполнению**, **Hold / On Hold**, **Backlog / Бэклог**.
Только в области «Остальные мои задачи» перед ними идёт **Open** (без учёта
регистра для приоритета), отдельно внутри каждого блока `NEW` → `Comment` → обычные.
Порядок статусов текущего спринта и режима эпиков не меняется.
Внутри одного приоритета и после них остальные названия идут по алфавиту; неизвестные статусы
не угадываются и не объединяются с похожими. Внутри одного статуса и блока меток
сначала идут задачи с более поздним последним изменением **`updated` в Jira**;
при одинаковом времени — по ключу задачи. Сравнивается полный момент времени,
включая доли секунды и часовой пояс, не дата создания, комментария или загрузки.
Задачи без корректного `updated` (в том числе без часового пояса) остаются видимыми
в конце своей группы, между собой — по ключу; обновление из-за такой даты не отклоняется.

После «Статуса» показана колонка **«Обновлено»**: дата того же изменения Jira
в формате `ДД.ММ.ГГГГ` в локальном часовом поясе macOS, без времени; для неизвестной
даты — `—`. Время влияет на сортировку, поэтому задачи с одинаковой видимой датой
могут идти не по ключу. Колонка есть в обеих областях и в режиме эпиков.
Щелчки по заголовкам столбцов и пустому пространству таблиц
не открывают браузер и не меняют локальные метки. Заголовки областей и их общие
количества задач сохранены. Выбор сохраняется за той же задачей при обновлении
и её перемещении между областями; стрелки и клавиши перехода перемещаются
по задачам.

### Режим эпиков

`e` заменяет обе области единым списком **«эпик → мои открытые тикеты»**;
повторное `e` возвращает обычный список. Поддерживается также кириллическая `е`.
Переключение использует уже загруженный снимок: не делает сетевых запросов,
не снимает метки и не пишет состояние. При новом запуске всегда выбран обычный
режим. Выбранный тикет сохраняется, если он есть в целевом представлении;
иначе выбирается доступная строка.

Показаны **твои открытые эпики**, включая пустые, и **родительские эпики твоих
открытых тикетов**, даже если сам эпик закрыт или назначен другому человеку.
Под каждым — только назначенные тебе задачи без resolution и не в статусе
`Verifying`, независимо от спринта. Подзадача наследует эпик родительского тикета;
чужой промежуточный тикет не показывается. Задачи без эпика здесь скрыты, но доступны в обычном режиме.

Эпики идут по ключу; строки эпиков выделены и содержат количество подходящих
тикетов, а тикеты показаны с отступом. Внутри каждого эпика сохраняется порядок
`NEW` → `Comment` → обычные, затем статус, время изменения Jira от нового к старому
и ключ при равном времени. Правило неизвестных дат такое же, как в обычном режиме.
Дата показана и у строк эпиков, но сами эпики по-прежнему идут по ключу.
Приоритет меток не переносит
тикет в другой эпик и не меняет порядок самих эпиков. Все группы всегда раскрыты.
Стрелки, PageUp/PageDown и Ctrl+Home/Ctrl+End перемещаются как по тикетам, так и
по эпикам; Enter или Ctrl+щелчок открывает выбранную задачу Jira, а не сворачивает группу.

На своих открытых эпиках сохраняются `NEW`/`Comment` и обычное подтверждение
показанного снимка при открытии. Дополнительно загруженные чужие или закрытые
эпики — только контекст: без меток, загрузки комментариев и записей в историю
наблюдения. Это относится и к родительским эпикам в `Verifying`: они остаются
контекстом для подходящих тикетов, но не входят в основную выборку. Их открытие
просто передаёт ссылку браузеру. Ошибка загрузки родителя/эпика отклоняет обновление
целиком, не заменяя успешный снимок неполным.

Обновление — при старте, по R и по умолчанию каждые **60 минут**, пока открыт TUI.
`refresh_seconds`: интервал в секундах, по умолчанию **3600**, от 5 до 86400.
Сохранённое значение из меню **S → Интервал обновления** имеет приоритет над TOML.
Без него используется явный `refresh_seconds` в TOML либо значение по умолчанию.
Циклы не перекрываются; сетевое ожидание не блокирует выход. При ошибке остаётся последний успешный обзор с пометкой
`УСТАРЕЛО`; до первого успеха показывается ошибка, не пустая успешная выборка.
`429 Retry-After` ограничивает также ручные повторы; показанное следующее время
учитывает первый допустимый автоматический цикл после этой задержки. Ручное
обновление не сбрасывает периодический таймер; пропущенные во время загрузки
циклы не ставятся в очередь.

## Локальные метки просмотра

Новые задачи отмечены зелёным **NEW**, задачи с непросмотренными комментариями —
жёлтым **Comment +N**. Это искусственные локальные метки, не метки и не статусы
в Jira. Если есть хотя бы одна метка, ключ и название выделены жирным;
при сочетании показываются обе метки. Цвета меток сохраняются на строке курсора,
а его фон по-прежнему обозначает выбор, не новизну. Без цвета признаки различимы
по тексту меток и жирности. Приоритет строк — `NEW` → `Comment` → обычные;
внутри каждого блока — статус, последнее изменение Jira от нового к старому,
затем ключ при равном времени; неизвестные даты в конце своей статусной группы.
При появлении или
снятии метки строка перемещается, но выбор остаётся на той же задаче.

- Основная выборка — задачи текущего аутентифицированного пользователя без
  resolution, кроме статуса `Verifying` (без учёта регистра), не состав всей команды.
  Исключение действует в обеих областях и для тикетов в режиме эпиков;
  похожие названия, например `Awaiting Verification`, не исключаются.
- Первый полностью успешный снимок создаёт baseline без массового `NEW`.
- Впервые появившаяся после baseline задача получает `NEW`, даже если создана
  давно. Существующие комментарии становятся исходными без уведомлений.
- Метки переживают обновление и перезапуск. Перемещение между спринтами,
  временное исчезновение и возврат известной задачи не создают повторный `NEW`.
- `Comment +N` считает новые доступные через API ID **чужих** комментариев.
  Собственные комментарии, изменение полей и редактирование известного
  комментария не дают уведомления; удаление и добавление не взаимопогашаются.
- Когда системный браузер **принимает ссылку**, снимается `NEW` и отмечаются
  просмотренными только комментарии показанного снимка. Более поздние
  комментарии при параллельном обновлении остаются непросмотренными.
  Успешное открытие не выводит отдельного уведомления. Отказ браузера и отказ
  записи явно сообщаются; отказ браузера не очищает метки.
- Это локальное наблюдение снимками, не журнал событий и **не доказательство
  чтения человеком**. Чтение в другом приложении/устройстве не синхронизируется.
  Появившиеся и исчезнувшие между опросами задачи/комментарии можно пропустить.

Термины: [GLOSSARY.md](GLOSSARY.md).

## Read-only контракт и хранение

Клиент делает только GET: `/rest/api/2/myself`, `/field`, `/search`,
`/issue/{id}/comment`, `/issue/{key}` (минимальные сведения о родителях/эпиках)
и `/rest/agile/1.0/sprint/{id}`. Поля Sprint, Epic Name и Epic Link определяются
по schema, без фиксированных customfield ID и без проверки английского названия
типа `Epic`. Используется стандартная конфигурация встроенных полей Jira Software:
заполненное обязательное поле Epic Name только у эпиков, Epic Link — ключ эпика.
См. [контракт Jira Software Server](https://docs.atlassian.com/jira-software/REST/7.13.0/#agile/1.0/epic)
и [контекст Epic Name в Data Center](https://support.atlassian.com/jira/kb/resolve-epic-name-requirement-on-create-issue-screen-in-jira/).
Если метаданные полей отсутствуют или неоднозначны, снимок отклоняется с явной
ошибкой. Сведения о спринтах — через Agile API, без фиксированной доски/ID.
Родители кэшируются в пределах одного цикла; их комментарии не запрашиваются,
если они сами не входят в основную выборку своих открытых задач. `--check`
проверяет и эту загрузку без записи состояния; его количества относятся
к основной выборке, без контекстных эпиков.
Поиск и комментарии полностью пагинируются; неполная, дублированная или
изменившая total пагинация отклоняет снимок целиком. API не даёт клиенту
транзакционный снимок всего сервера: иногда требуется повторное обновление.

TLS проверяется; **все HTTP-редиректы отклоняются**. Токен не передаётся другому
origin. Таймаут — 15 секунд на операцию и 120 секунд на полный цикл.
Браузер вызывается через `/usr/bin/open` со списком аргументов без shell;
URL сохраняет context path и содержит проверенный ключ задачи.

Состояние — `$XDG_STATE_HOME/jira-overview` или `~/.local/state/jira-overview`,
либо `state_dir` из TOML. SHA-256-профиль зависит от URL instance и стабильной
идентичности пользователя. Формат JSON версии 1 не изменён: версия, baseline,
ID задач, `NEW` и исходные/просмотренные ID комментариев. Названия, статусы,
авторы, тела комментариев и PAT не сохраняются. Локальные ID всё равно приватны:
**не публикуйте файлы состояния**. Новые каталоги — 0700, файлы — 0600;
разрешения существующих каталогов приложение не меняет.

Запись атомарна, файловый lock не допускает второй экземпляр профиля.
Lock освобождается ОС после выхода; пустой `.lock` можно оставить.

Если прежнюю вкладку найти не получается, в окне с ошибкой нажмите **P**:

- Приложение ищет процесс, открывший **lock именно этого профиля**, а не все
  процессы Python/Jira Warrior. Поиск асинхронный; **Q** по-прежнему позволяет выйти.
- Найденный PID показывается в отдельном окне. По умолчанию выбрана **«Отмена»**;
  Enter без смены выбора или Esc ничего не завершают. Для остановки выберите
  **«Завершить»** мышью либо Tab и Enter. Сам поиск сигналов не посылает.
  Пока открыто подтверждение, новые циклы загрузки пропускаются, чтобы таймер
  не сбрасывал найденного владельца; после отмены обычное обновление возобновляется.
- После подтверждения заново сверяются lock, PID, пользователь ОС, время запуска
  и распознаваемая команда. Только этому экземпляру отправляется **SIGINT**.
  После освобождения профиля текущий TUI повторяет загрузку автоматически.
  Если другой процесс уже завершился, загрузка повторяется без сигнала.
- При неоднозначности, смене владельца, неизвестной команде, отказе инструментов
  или прав показывается безопасная ошибка. Если профиль не освободился за три
  секунды, автоматической эскалации нет: закройте прежний экземпляр вручную
  и нажмите **R**. `killall`, sudo и принудительный SIGKILL не используются.

Поиск использует штатные macOS `lsof` и `ps`. Поддерживаются также старые пустые
lock-файлы; PID/аргументы в них не записываются. Аргументы процессов используются
только для локальной проверки команды и не выводятся/не сохраняются.
На macOS проверка процесса и отправка сигнала не атомарны: повторная проверка
снижает риск смены PID, но не является атомарным дескриптором процесса.
**Ни `.lock`, ни историю меток удалять для восстановления не нужно.**

Для резервной копии завершите приложение и сохраните каталог приватно.
Повреждённый JSON не заменяется baseline — восстановите исправную копию при
остановленном приложении. Удаление профиля сбрасывает историю; это не способ
исправить обычную сетевую ошибку.

## Разработка и проверки

В корне отдельного клона:

```sh
uv sync --frozen --python 3.12
```

Полный синтетический набор:

```sh
PYTHONDONTWRITEBYTECODE=1 uv run --frozen python -m unittest discover -s tests -v
```

Обновлением и открытием владеет независимая от Textual `ReviewSession`: TUI
передаёт ручное обновление и захваченный при выборе снимок задачи, а отображает
её неизменяемое текущее представление. Сессия сериализует одинаковые операции,
сохраняет последний успешный обзор при ошибке и освобождает профиль только
после остановки фоновых работ.

Представлением обзора владеет составной Textual module `OverviewPresentation`
в `src/jira_overview/presentation.py`: таблицы и заголовки, группы по статусу,
режим эпиков, общие ширины, высота спринта и сохранение выбранной задачи.
`Overview` передаёт согласованные `ReviewItem` через `present`, переключает режим
через `toggle_epics` и передаёт управление панели через
`suspend_navigation` / `resume_navigation`. Обновления во время панели не забирают
фокус; событие `IssueActivated` несёт точный показанный снимок для открытия
Сессией обзора. Управление панелями, уведомления и заголовок соединения остаются
в `Overview`; сеть и хранение локальных меток в представление не перенесены.

Прямые проверки `tests/test_presentation.py` используют этот interface и Pilot
в небольшом тестовом App без HTTP и запуска Сессии обзора: загрузка/пустой обзор,
порядок и области, эпики, ширины, сохранение выбора, приостановка навигации и
отложенная обработка показанного снимка. Сквозные проверки настоящего приложения
сохранены для мыши/клавиатуры, размеров, панелей и взаимодействия с сессией.

Тесты используют настоящий Textual Pilot, HTTPX, loopback HTTP-сервер и
временное состояние. HTTP разрешён только явно выбранному тестовому
конструктору: CLI требует HTTPS. Передача ссылки перехватывается; реальные
Jira, credentials и браузер не используются. Проверяются baseline/NEW,
комментарии, перезапуск, выбор/мышь/размеры, гонки, пагинация, ошибки,
сортировка по `updated` (часовые пояса, доли секунды, равные/неизвестные даты),
локальная дата в колонке «Обновлено» и сохранение выбора при перестановке,
lock/отказ записи, read-only, редиректы, автообновление и отзывчивый выход.
Для режима эпиков покрыты переключение/перезапуск, единая группировка через
спринты, пустые и контекстные эпики, наследование подзадач, сортировка/метки,
навигация/мышь/размеры, обнаружение полей по schema, кэш родителей, ошибочные
связи и сохранение успешного снимка. Гонка открытия контекстного эпика с его
появлением в основной выборке не подтверждает более свежие метки.
Панель тем проверяется через клавиатуру и мышь: группировка, немедленные цвета,
подтверждение/отмена, возврат фокуса, обновление и режим эпиков, изменение размера,
перезапуск, ошибки чтения/атомарной записи и отсутствие изменений истории/Jira.
Панель настроек проверяется клавиатурой и мышью: ввод/валидация/отмена,
немедленное изменение расписания, перезапуск/приоритет над TOML, ошибки записи,
совместимость с темами, возврат фокуса, размеры и отсутствие изменений истории/Jira.
Восстановление занятого профиля проверяется на собственных дочерних процессах
и временных lock-файлах: поиск, подтверждение/отмена, SIGINT без эскалации,
смена идентичности/PID, посторонний пользователь/команда/профиль, безопасный отказ,
автоматическое обновление и отмена поиска при выходе. Реальные пользовательские
процессы тестами не завершаются.
Проверки установленного CLI покрывают команду и прежние пути конфигурации.
Три теста Go Task используют настоящий Task и fake CLI; без Task пропускаются
только они. Координация сессии отдельно проверяется через тот же публичный
interface `start` / `refresh` / `open` / `view` / `interval` / `set_interval` /
`aclose`, без запуска TUI.
Статический typechecker не настроен.

Живая read-only приёмка отдельно проверяет версию окружения и Jira, `--check`
без изменения состояния, обе области TUI, R, передачу одной ссылки браузеру
и выход Q с восстановлением терминала. Она не создаёт задачи/комментарии и
не подтверждает синтетические переходы NEW реальными корпоративными событиями.
Приватные конфигурации, состояния и сырые терминальные логи не входят в релиз.
