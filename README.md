# jirawarrior-tui

Read-only TUI для своих незавершённых задач в **Jira Server/Data Center**:
две постоянно видимые области **«Текущий спринт»** и **«Остальные мои задачи»**,
локальные метки `NEW` и `+N комм.`, обновление и открытие задачи в браузере.
Команда остаётся **`jira-overview`**. Интеграции с Taskwarrior нет.

Первый выпуск поддерживает **только macOS**, Python **3.11+**,
[uv](https://docs.astral.sh/uv/) и Git для установки из тега.
Linux, Windows, Jira Cloud, Basic auth, cookies, запись в Jira и командные
дашборды не поддерживаются. Нужен Jira Software с доступным Agile API и Bearer PAT;
наличие PAT в Server/DC само по себе не гарантирует совместимость всех API.
Приложение не устанавливает фоновые службы и не меняет настройки системы.

## Установка из релиза

Установите опубликованный тег **v0.1.0** в отдельное uv tool-окружение:

```sh
uv tool install --python 3.12 'git+https://github.com/aprudkin/jirawarrior-tui.git@v0.1.0'
```

Python 3.12 выбран для воспроизводимого сценария первого выпуска; uv при
необходимости загрузит интерпретатор. Клон `ossetup` или этого проекта для
запуска не нужен. Если каталог uv tools ещё не в PATH, выполните `uv tool update-shell`
и откройте новый терминал. После установки из любого каталога:

```sh
jira-overview --help
```

Textual **6.6.0** и HTTPX **0.28.1** закреплены в метаданных пакета.
`uv.lock` закрепляет транзитивные зависимости **для разработки через `uv sync --frozen`**;
`uv tool install` из тега использует метаданные пакета, а не этот lockfile.
PyPI/Homebrew-публикации нет. См. [описание выпуска](CHANGELOG.md).

## Конфигурация и PAT

Создайте приватный `~/.config/jira-overview/config.toml` либо
`$XDG_CONFIG_HOME/jira-overview/config.toml` по [синтетическому примеру](config.example.toml):

```toml
url = "https://jira.example.org/jira"
token_env = "MY_JIRA_TOKEN"
refresh_seconds = 60
# state_dir = "~/.local/state/jira-overview"
```

Замените только адрес и, при необходимости, имя переменной. `url` — HTTPS-адрес
instance с возможным context path, без `/rest/...`, query и fragment.
TOML храните вне Git с доступом только владельцу. Пример не содержит реальных
адресов, токена или ID и не является рабочей корпоративной конфигурацией.

По [инструкции Atlassian](https://confluence.atlassian.com/enterprise/using-personal-access-tokens-1026032365.html)
PAT создаётся в Jira через **аватар → Profile → Personal access tokens → Create token**.
Задайте имя и срок действия, скопируйте токен в защищённое хранилище: повторно
показать его нельзя. Если раздел недоступен, обратитесь к администратору;
приложение не обходит политику instance. PAT наследует права пользователя и
**не становится read-only** от использования этим клиентом: GET-only — контракт
приложения, а не ограничение возможностей украденного PAT. Используйте минимально
необходимые права и отзовите скомпрометированный токен в том же разделе Jira.

`token_env` — **имя** экспортированной переменной окружения, не сам токен.
Приложение не читает shell-файлы и не загружает `.env`. Предпочтителен уже
настроенный менеджер секретов. Для разовой сессии **zsh** можно ввести PAT скрыто,
без помещения значения в команду или shell history:

```zsh
read -rs 'MY_JIRA_TOKEN?Bearer PAT: ' && export MY_JIRA_TOKEN
```

Не записывайте PAT в TOML, аргументы команд, Git, скриншоты или отчёты.
Переменную наследуют дочерние процессы терминала. После работы удалите её
из текущей сессии командой `unset MY_JIRA_TOKEN`.

Проверка соединения, включая все страницы комментариев, **без UI и записи состояния**:

```sh
jira-overview --check
```

Она печатает только итог и количества: без URL, имени пользователя, ключей
задач, комментариев или токена. Для другого TOML есть `--config`.
Открыть TUI:

```sh
jira-overview
```

## Необязательные `t jira` / `t jira:check`

Go Task не нужен для прямого запуска. Если он уже установлен, сохраните
[Taskfile.yml](Taskfile.yml) из того же тега вне репозитория:

```sh
curl -fL --create-dirs --output "$HOME/.config/jira-overview/Taskfile.yml" https://raw.githubusercontent.com/aprudkin/jirawarrior-tui/v0.1.0/Taskfile.yml
```

Добавьте или замените **только** запись `jira` в существующем `includes`
глобального Taskfile, не заменяя другие задачи и не создавая второй `includes`:

```yaml
includes:
  jira:
    taskfile: ~/.config/jira-overview/Taskfile.yml
    optional: true
    flatten: true
```

Обёртки вызывают установленный `jira-overview` / `jira-overview --check`,
наследуют окружение, сохраняют TTY и не зависят от checkout или `uv run`.
Канонические имена — `open:jira` / `check:jira`, алиасы — `jira` / `jira:check`.
Для zsh короткий глобальный вызов с сохранением кода ошибки задаётся так:

```zsh
alias t='noglob command task --global --exit-code'
```

После этого доступны `t jira` и `t jira:check` из любого каталога.
Без алиаса используйте `task --global --exit-code jira` или
`task --global --exit-code jira:check`. `--exit-code` сохраняет точный код
дочерней команды. Отсутствующий optional include не мешает остальным задачам.

## Переход с ossetup

Команда, Python-модуль `jira_overview`, TOML, XDG-переменные и каталог состояния
`jira-overview` сохранены. Меняется только имя дистрибутива:
`ossetup-jira-overview` → `jirawarrior-tui`. **Не удаляйте состояние ради переноса**:
baseline, `NEW` и непросмотренные комментарии не требуют миграции или сброса.
Завершите старый экземпляр перед запуском нового — профиль защищён lock.

Если использовался старый Go Task include `~/dev/ossetup/jira-tui/Taskfile.yml`,
замените только его путь по инструкции выше после установки нового пакета.
Не запускайте две копии одновременно. Единственный поддерживаемый исходник —
этот репозиторий; история `ossetup` не импортирована, атрибуция сохранена
в [NOTICE.md](NOTICE.md).

## Управление

| Действие | Клавиша / жест |
| --- | --- |
| Выбор строки | ↑ / ↓; Ctrl+Home / Ctrl+End; PageUp / PageDown |
| Переключение области | Tab / Shift+Tab |
| Открытие задачи | Enter или один щелчок по строке |
| Ручное обновление | R |
| Выход | Q или Ctrl+C |

Высота «Текущего спринта» подстраивается под список: после таблицы (включая
горизонтальную полосу прокрутки, если она нужна) остаются ровно **три пустые
строки**, затем начинается «Остальные мои задачи». При обновлении и изменении
размера окна начало нижней области пересчитывается. Длинный спринт ограничен
по высоте, чтобы обе области оставались видимыми и прокручивались независимо.
Горизонтальная прокрутка — стрелки влево/вправо и Home/End; ключ и метки находятся
в первом столбце. Рекомендуемый
минимум терминала — 45×16. Несколько активных спринтов показаны с именами и ID,
задача остаётся одной строкой. Верхняя строка содержит пользователя и время
последней успешной загрузки. Jira-текст выводится без Rich-разметки и
управляющих символов.

В каждой области задачи сгруппированы по точному названию статуса: одинаковые
названия объединяются, в том числе между проектами; разные названия остаются
отдельными группами. Непустые группы всегда раскрыты, без названий и счётчиков
групп. В обеих областях строки задач идут подряд, без пустых строк перед первой
группой и между группами. Статус по-прежнему виден в столбце «Статус».
Порядок приоритетов (названия сравниваются
без учёта регистра только для определения приоритета): **In Progress / В работе**,
**To Do / К выполнению**, **Hold / On Hold**, **Backlog / Бэклог**. Внутри одного
приоритета и после них остальные названия идут по алфавиту; неизвестные статусы
не угадываются и не объединяются с похожими. Внутри группы сохраняется порядок
по ключу задачи. Щелчки по заголовкам столбцов и пустому пространству таблиц
не открывают браузер и не меняют локальные метки. Заголовки областей и их общие
количества задач сохранены. Выбор сохраняется за той же задачей при обновлении
и её перемещении между областями; стрелки и клавиши перехода перемещаются
по задачам.

Обновление — при старте, по R и каждые 60 секунд, пока открыт TUI.
`refresh_seconds`: от 5 до 86400 секунд. Циклы не перекрываются; сетевое ожидание
не блокирует выход. При ошибке остаётся последний успешный обзор с пометкой
`УСТАРЕЛО`; до первого успеха показывается ошибка, не пустая успешная выборка.
`429 Retry-After` ограничивает также ручные повторы.

## Локальные метки просмотра

Новые задачи отмечены зелёным **NEW**, задачи с непросмотренными комментариями —
жёлтым **+N комм.** Если есть хотя бы одна метка, ключ и название выделены жирным;
при сочетании показываются обе метки. Цвета меток сохраняются на строке курсора,
а его фон по-прежнему обозначает выбор, не новизну. Без цвета признаки различимы
по тексту меток и жирности. Метки не меняют порядок задач внутри групп.

- Основная выборка — задачи текущего аутентифицированного пользователя без
  resolution, не состав всей команды.
- Первый полностью успешный снимок создаёт baseline без массового `NEW`.
- Впервые появившаяся после baseline задача получает `NEW`, даже если создана
  давно. Существующие комментарии становятся исходными без уведомлений.
- Метки переживают обновление и перезапуск. Перемещение между спринтами,
  временное исчезновение и возврат известной задачи не создают повторный `NEW`.
- `+N комм.` считает новые доступные через API ID **чужих** комментариев.
  Собственные комментарии, изменение полей и редактирование известного
  комментария не дают уведомления; удаление и добавление не взаимопогашаются.
- Когда системный браузер **принимает ссылку**, снимается `NEW` и отмечаются
  просмотренными только комментарии показанного снимка. Более поздние
  комментарии при параллельном обновлении остаются непросмотренными.
  Успешное открытие не выводит отдельного уведомления. Отказ браузера и отказ
  записи явно сообщаются; отказ браузера не очищает метки.
- Это локальное наблюдение снимками, не журнал событий и **не доказательство
  чтения человеком**. Чтение в другом приложении/устройстве не синхронизируется.
  Появившиеся и исчезнувшие между опросами задачи/комментарии можно пропустить.

Термины: [GLOSSARY.md](GLOSSARY.md).

## Read-only контракт и хранение

Клиент делает только GET: `/rest/api/2/myself`, `/field`, `/search`,
`/issue/{id}/comment` и `/rest/agile/1.0/sprint/{id}`. Поле Sprint определяется
по schema, сведения о спринтах — через Agile API, без фиксированной доски/ID.
Поиск и комментарии полностью пагинируются; неполная, дублированная или
изменившая total пагинация отклоняет снимок целиком. API не даёт клиенту
транзакционный снимок всего сервера: иногда требуется повторное обновление.

TLS проверяется; **все HTTP-редиректы отклоняются**. Токен не передаётся другому
origin. Таймаут — 15 секунд на операцию и 120 секунд на полный цикл.
Браузер вызывается через `/usr/bin/open` со списком аргументов без shell;
URL сохраняет context path и содержит проверенный ключ задачи.

Состояние — `$XDG_STATE_HOME/jira-overview` или `~/.local/state/jira-overview`,
либо `state_dir` из TOML. SHA-256-профиль зависит от URL instance и стабильной
идентичности пользователя. Формат JSON версии 1 не изменён: версия, baseline,
ID задач, `NEW` и исходные/просмотренные ID комментариев. Названия, статусы,
авторы, тела комментариев и PAT не сохраняются. Локальные ID всё равно приватны:
**не публикуйте файлы состояния**. Новые каталоги — 0700, файлы — 0600;
разрешения существующих каталогов приложение не меняет.

Запись атомарна, файловый lock не допускает второй экземпляр профиля.
Lock освобождается ОС после выхода; пустой `.lock` можно оставить.
Для резервной копии завершите приложение и сохраните каталог приватно.
Повреждённый JSON не заменяется baseline — восстановите исправную копию при
остановленном приложении. Удаление профиля сбрасывает историю; это не способ
исправить обычную сетевую ошибку.

## Разработка и проверки

В корне отдельного клона:

```sh
uv sync --frozen --python 3.12
```

Полный синтетический набор:

```sh
PYTHONDONTWRITEBYTECODE=1 uv run --frozen python -m unittest discover -s tests -v
```

Обновлением и открытием владеет независимая от Textual `ReviewSession`: TUI
передаёт ручное обновление и захваченный при выборе снимок задачи, а отображает
её неизменяемое текущее представление. Сессия сериализует одинаковые операции,
сохраняет последний успешный обзор при ошибке и освобождает профиль только
после остановки фоновых работ.

Тесты используют настоящий Textual Pilot, HTTPX, loopback HTTP-сервер и
временное состояние. HTTP разрешён только явно выбранному тестовому
конструктору: CLI требует HTTPS. Передача ссылки перехватывается; реальные
Jira, credentials и браузер не используются. Проверяются baseline/NEW,
комментарии, перезапуск, выбор/мышь/размеры, гонки, пагинация, ошибки,
lock/отказ записи, read-only, редиректы, автообновление и отзывчивый выход.
Проверки установленного CLI покрывают команду и прежние пути конфигурации.
Три теста Go Task используют настоящий Task и fake CLI; без Task пропускаются
только они. Координация сессии отдельно проверяется через тот же публичный
interface `start` / `refresh` / `open` / `view` / `aclose`, без запуска TUI.
Статический typechecker не настроен.

Живая read-only приёмка отдельно проверяет версию окружения и Jira, `--check`
без изменения состояния, обе области TUI, R, передачу одной ссылки браузеру
и выход Q с восстановлением терминала. Она не создаёт задачи/комментарии и
не подтверждает синтетические переходы NEW реальными корпоративными событиями.
Приватные конфигурации, состояния и сырые терминальные логи не входят в релиз.
